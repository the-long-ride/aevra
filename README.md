**aevra** lets AI assistants such as ChatGPT, Claude, and Grok work directly on your machine: edit files, run commands, manage Git repositories, automate desktop software, and drive browsers under explicit security boundaries.

When an AI assistant requests an action, aevra checks the request against your configured capability profile, prompts for human approval on sensitive operations, and records each action to an audit log.

It supports any client using the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) standard, runs on Windows, macOS, and Linux, and connects over local networks, public tunnels, or private VPNs.

> **The central invariant:** The Core decides authority. The Worker executes only the exact authority it receives.

## What makes aevra different?

- **Batch operations with bounded concurrency:** First-class `file_read_many`, `file_write_many`, and `command_run_many` tools reduce model round trips, paired with parallel regex search (`search`).
- **Silent background desktop automation:** Interact with native Windows applications through UI Automation pattern tools without moving the mouse cursor, changing clipboard contents, or stealing keyboard focus. See the [desktop control guide](https://github.com/the-long-ride/aevra/blob/main/docs/user-manual/19-desktop-control.md).
- **Secure browser automation:** Drive Chromium browsers through the Aevra MV3 extension or Chrome DevTools Protocol (CDP) under strict DLP, risk, and approval controls, with automatic refusal on password, OTP, or payment fields. See the [browser control guide](https://github.com/the-long-ride/aevra/blob/main/docs/user-manual/18-browser-control.md).
- **Host system detection:** Non-blocking probes discover 11 toolchain categories (Git, Node, Python, .NET, Rust, Go, JVM, Ruby, PHP, C/C++, Docker/Podman) and find recommended shells (`pwsh`, `powershell`, `cmd`, `bash`, `zsh`, `sh`) automatically.
- **Security boundaries and data masking:** A central `SecurityGuard` boundary denies `SECRET` paths, masks `SENSITIVE` data, applies real-time DLP redaction, and protects against symlink and hard-link alias attacks.
- **Configurable local transport:** Supports HTTPS and HTTP loopback gateway protocols with internal HTTPS isolation and runtime transport security checks.
- **Native service management:** Runs as a user background service on Windows (Scheduled Tasks, named pipes, DPAPI), Linux (`systemd --user`, unix domain sockets, Secret Service), and macOS (`LaunchAgents`, Keychain).
- **Capability profiles and step-up approvals:** Multi-tier capability profiles (Minimal, Read-Only, Safe Dev, Power Dev, Full Access, Custom), interactive human-in-the-loop approvals, and `policy.critical.alwaysConfirm` for sensitive actions.
- **Background processes and change sets:** Named background processes (`process_start`, `process_wait`, `process_logs`) with detached completion sidecars, journaled multi-file change sets with rollback, and safe 3-way auto-merging for concurrent edits.
- **Provider-neutral ingress:** Connect directly via Direct HTTPS, Cloudflare Access tunnels, managed ngrok, Caddy, Tailscale Funnel, FRP, or reverse SSH with OAuth 2.0 PKCE authentication.
- **OAuth connection continuity:** Short-lived access credentials and rotating refresh families reconnect to the same durable logical connection, keeping workspace authority intact across reconnects.

## Core features

- **67 built-in MCP tools and fast lane interfaces:** Includes batch file operations, command execution, workspace management, Git actions, background processes, change sets, browser automation, and desktop control. Upstream MCP tools load dynamically under namespaced names.
- **Background desktop automation (Windows):** Windows UI Automation (UIA) tools (`desktop_invoke`, `desktop_set_value`, `desktop_select`, `desktop_toggle`, `desktop_release_window`, and `desktop_describe` in background mode) interact with applications without moving the mouse cursor, changing clipboard contents, or stealing keyboard focus. Actions require an exclusive 60-second window lease, invalidate snapshots immediately on state changes, suspend automatically on focus shifts, and reject unprivileged access to elevated or secure desktop windows. See the [desktop control guide](https://github.com/the-long-ride/aevra/blob/main/docs/user-manual/19-desktop-control.md).
- **Foreground desktop control (Windows):** Ten `desktop_*` tools inspect window hierarchies, target controls using cached element references, capture on-demand screenshots, and inject clicks, keystrokes, and scroll events. Gated by capability profiles, window attribution checks, and interactive user approvals.
- **Browser control and extension integration:** Nine `browser_*` tools drive Chromium browsers through the Aevra MV3 browser extension or Chrome DevTools Protocol (CDP) under capability, risk, approval, DLP, and audit controls. Prevents page-script evaluation and rejects inputs into password, OTP, or payment fields. The Web UI and `aevra status` report pairing state, with download and load-unpacked instructions via `aevra extension install`. See the [browser control guide](https://github.com/the-long-ride/aevra/blob/main/docs/user-manual/18-browser-control.md).
- **Floating-IP OAuth continuity and runner leases:** Decouples authentication and workspace authority from ephemeral cloud runner IP pools used by ChatGPT and Claude. Persists workspace grants across rotating IPs, adds atomic approval claims (`claimExecution`) to prevent double execution, shares connection rate limiters, and retains runner origin IPs in audit logs for 24 hours.
- **Host system capabilities:** The `aevra_status` MCP tool reports toolchains, available shells, and execution defaults to models and the Admin UI.
- **Dynamic resources and instruction prompts:** Serves context files via MCP resources (`aevra://skill/<source>/<name>`) and instruction prompts parsed from `AGENTS.md` and `CLAUDE.md`.
- **MCP upstream proxy:** Connect external HTTP, SSE, or stdio MCP servers through the Admin UI or `aevra mcp`. Upstream tools republish under collision-resistant namespaced identifiers, with secret-backed credentials and catalog fingerprinting that pauses serving if schemas change unexpectedly. See the [MCP upstreams guide](https://github.com/the-long-ride/aevra/blob/main/docs/user-manual/20-mcp-upstreams.md).
- **Workspace manifest (`aevra.json`):** Workspaces can advertise build, test, and lint commands, and declare sensitive or secret path globs that feed directly into the file security boundary. See the [manifest design specification](https://github.com/the-long-ride/aevra/blob/main/docs/specs/2026-09-12-aevra-manifest-design.md).
- **Configuration backup and restore:** Download and restore complete gateway configurations as JSON through the Admin UI Data tab (`/api/data/export` and `/api/data/import`), excluding machine-specific secrets for safe portability.
- **React 19 Admin dashboard:** Single-page dark theme dashboard with an edge-to-edge Request Activity timeline, universal switch toggles, upward-anchored dropdowns, live capability status, and modal confirmations for danger actions.
- **Out-of-process worker sandbox:** The execution worker runs in an isolated child process over authenticated local IPC, with Docker and Podman container sandboxing support.

## Quick installation

Install aevra globally via npm and start the gateway on your operating system:

### Windows (PowerShell)

```powershell
# 1. Install aevra globally
npm install -g @the-long-ride/aevra@latest

## Choose 2.1 or 2.2:

# 2.1 Configure admin credentials for User scope (persists across sessions):
[System.Environment]::SetEnvironmentVariable('AEVRA_USERNAME', 'admin', 'User')
[System.Environment]::SetEnvironmentVariable('AEVRA_PASSWORD', 'YourSecurePassword', 'User')

# 2.2. Apply to current session only:
# $env:AEVRA_USERNAME = 'admin'
# $env:AEVRA_PASSWORD = 'YourSecurePassword'

# Start aevra with dashboard in browser
aevra start --ui
```

### macOS and Linux (zsh / bash)

```bash
# 1. Install aevra globally
npm install -g @the-long-ride/aevra@latest

# 2. Configure admin credentials and launch daemon with Web UI
export AEVRA_USERNAME="admin"
export AEVRA_PASSWORD="YourSecurePassword"
aevra start --ui
```

_(Optional)_ Run aevra automatically as a user-level background service:

```bash
aevra service install
aevra service start
```

## Quick connect guide

aevra exposes a standard MCP endpoint (`/mcp`) that can be accessed directly over HTTPS (such as `https://localhost:47830/mcp` or direct IP/domain) or exposed to the internet through a tunnel (Cloudflare Tunnel, ngrok, Tailscale Funnel, Caddy, FRP, reverse SSH).

### 1. Connect ChatGPT (Custom Action)

1. In ChatGPT, create a new Custom Plugin / Action:
   - **Name**: `aevra` (or any custom name)
   - **Server URL**: `https://<your-aevra-host>/mcp` (your tunnel or public URL)
   - **Authentication**: `OAuth`
2. ChatGPT initiates the OAuth 2.0 PKCE discovery flow. Open your local aevra Web UI (`https://localhost:47831`) and click **Allow** on the pairing request.
3. Under ChatGPT plugin settings, grant **Permission for Plugins -> Allow all actions** so commands and tool calls execute through aevra without recurring client confirmation dialogs.

### 2. Connect Claude, Grok, and other MCP clients

Claude example:

1. Open Claude, navigate to account **Settings**, then select **Connectors**.
   - **Name**: `aevra` (or any custom name)
   - **Server URL**: `https://<your-aevra-host>/mcp` (your tunnel or public URL)
   - **Authentication**: `OAuth`
2. Approve the OAuth request in the aevra Web UI, following the same flow as ChatGPT.

### OAuth connection continuity

Aevra cannot guarantee that an HTTP or MCP transport remains open indefinitely. It maintains logical continuity across reconnects by accepting short-lived access tokens and rotating refresh tokens against the same connection record.

Access tokens expire after 60 minutes by default, refresh token families last up to 30 days, and interrupted MCP sessions retain a 15-minute grace window for reconnects. Durable connections preserve remembered workspace grants and connection-level policies, while session-only leases expire on disconnect.

Aevra does not automatically replay a lost mutating request after reconnection. Call `operation_get` or `operation_list` to inspect the status of a previous operation before issuing another write, commit, delete, or command.

## Tips

<details>
<summary><strong>Remote device control and desktop automation</strong></summary>

- **Automate machines remotely:** When running Aevra as a background service on Windows, an AI assistant connected through ChatGPT or Claude can control native desktop applications, system utilities, and local tools over a secure tunnel or HTTPS without needing a remote desktop viewer.
- **Prefer background automation:** Use `desktop_describe(mode: 'background')` with action tools (`desktop_invoke`, `desktop_set_value`, `desktop_select`, `desktop_toggle`). These use Windows UI Automation control patterns without moving the mouse cursor, typing into the active window, or stealing keyboard focus. You can continue using the computer while the agent works in the background, and tasks continue even when physical displays turn off.
- **Fall back to foreground control when needed:** If an application uses custom canvas rendering, game viewports, or custom controls lacking accessibility trees, switch to foreground tools (`desktop_click`, `desktop_type`, `desktop_key`, `desktop_capture`). Foreground actions require identifiable windows and prompt for user approval before clicks and keystrokes.
- **Window leases and snapshots:** Background automation holds an exclusive 60-second window lease. Each mutating action invalidates the snapshot to prevent stale handles. If a dialog appears or foreground focus changes, Aevra suspends the lease and returns `DESKTOP_FOCUS_CHANGED`. The agent should call `desktop_describe` to inspect the new layout before continuing.
- **Security boundaries:** Windows User Interface Privilege Isolation (UIPI) prevents standard-user processes from injecting input into elevated windows. Aevra refuses input to unattributable windows, elevated processes, UAC dialogs, and secure desktop screens.
- **Supervise approvals remotely:** High-risk desktop actions require confirmation. Keep the Aevra Web UI open on a phone, tablet, or separate browser to review and approve commands without switching away from the active app on the host.

</details>

<details>
<summary><strong>Browser control and web automation</strong></summary>

- **Automate logged-in web sessions:** Install the Aevra MV3 browser extension to drive your primary browser profile. The AI can navigate internal portals, SaaS dashboards, and web consoles that already have active login sessions without exporting cookies or exposing credentials to the model.
- **Pairing and status:** Pair the browser in Settings under Browser control with a single-use pairing code. The top navigation bar in the Web UI shows connection status with a green dot when connected and a red dot when disconnected.
- **Credential protection:** Aevra blocks commands targeting password, one-time code (OTP), or payment fields. Log into sensitive services yourself and tell the agent to resume once authentication is complete.
- **Prefer accessibility snapshots:** Instruct the agent to call `browser_snapshot` rather than taking full-page screenshots. DOM accessibility snapshots cost fewer tokens and give reliable element references for `browser_act_many`.
- **Isolated automation with CDP:** For unattended browser tasks that should not touch personal tabs or history, configure Aevra to connect through Chrome DevTools Protocol (CDP) to a dedicated Chromium instance running with `--remote-debugging-port`.
- **Restricted URL schemes:** Aevra blocks navigation to local loopback administrative ports, internal `chrome://` settings pages, and local `file://` URIs to prevent prompt injection attacks against the host.

</details>

<details>
<summary><strong>Security</strong></summary>

- **Rotate credentials:** Update `AEVRA_USERNAME` and `AEVRA_PASSWORD` in your user environment or shell profile, then restart aevra.
- **Scope tunnel exposure:** Expose the MCP endpoint (`publicUrl`) for AI clients. Keep the Admin UI local unless you configure an explicit HTTPS `adminPublicUrl` with trusted Admin origins.
- **Use capability profiles:** Assign the lowest required profile per connector in the Web UI, such as `Read-Only` or `Safe Dev` for AI web clients, reserving `Full Access` for trusted local sessions.
- **Audit activity:** Review the audit log in the Web UI Activity tab to inspect tool calls and policy decisions.

</details>

<details>
<summary><strong>Performance</strong></summary>

- **Scope workspace search:** Use `search` with explicit `include` and `exclude` glob patterns. Target specific subdirectories in large repositories to keep searches fast.
- **Use managed processes for long tasks:** Run long builds or test suites with `process_start` and `process_wait` rather than blocking terminal commands. Aevra tracks them across reconnects.
- **Use change sets for multi-file edits:** Journaled change sets allow rolling back multi-file edits in one step if a task fails halfway through.
- **Run as a background service:** Install Aevra with `aevra service install && aevra service start` so the gateway starts on boot and reconnects automatically.

</details>

<details>
<summary><strong>Remote work through AI chat web interfaces</strong></summary>

- **Save generated assets:** Ask ChatGPT or Claude to use `file_write` to save images, diagrams, or generated data directly into your local project folder.
- **Run research and reporting:** Have the AI search your notes and data directories with `search`, summarize the findings, and write the report to a local file.
- **Code collaboration:** Point ChatGPT or Claude at your local repository to read files, run tests, apply edits, and commit changes in a single conversation.
- **Document processing:** Have AI clients read, draft, and update local markdown, CSV, and text files directly from chat.
- **Multi-client workflows:** Connect multiple AI tools at the same time, giving each connector its own capability profile.
- **Mobile development:** Use ChatGPT or Claude mobile apps to inspect repositories, run test suites, or generate files on your remote workspace while away from your desk.

</details>

<details>
<summary><strong>Remote server setups and headless devices</strong></summary>

- **Always-on servers:** Run Aevra as a background service on a VPS, home lab server, or NAS to keep workspaces and background processes available without keeping a laptop powered on.
- **Remote Admin dashboard:** Access the Web UI over a private network (such as Tailscale or WireGuard) or behind an authenticated reverse proxy to monitor activity and adjust workspace grants from a phone or tablet.
- **Mobile approvals:** Approve or reject critical operations from your phone when an AI client requests a sensitive tool call.
- **Split-plane network isolation:** Publish the MCP `publicUrl` for AI clients while keeping `adminPublicUrl` restricted to a private VPN or trusted origin.

</details>

<details>
<summary><strong>Hooks</strong></summary>

- **Pre- and post-tool hooks:** Configure `hooks.pre` and `hooks.post` in `aevra.config.json` to run scripts before or after specific MCP tool calls, such as linting before a commit or notifying a webhook after a file write.
- **Block unwanted operations:** A pre-hook that exits with a non-zero status cancels the tool call. Use this to prevent destructive commands in specific directories.
- **Per-workspace configuration:** Hooks are defined per workspace configuration file and stay scoped to that project.

</details>
